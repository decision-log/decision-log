# STT 공급자 요건

특정 공급자를 확정하지 않는다. 대신 **우리가 요구하는 것**을 적어두고, 이 목록으로 후보를 평가한다.

Soniox로 한 차례 실측했으나 채택하지 않는다. 그 실측의 성과는 공급자 선택이 아니라 **아래 요건 목록을 알게 된 것**이다.

다만 v1을 만들려면 무엇이든 하나는 붙어야 한다. **Soniox를 임시 구현체로 쓴다** — 계정이 있고 아래 요건을 전부 충족하는 것이 확인됐다. 채택이 아니라 자리 채우기이며, **STT는 인터페이스 뒤에 둔다.** 인터페이스가 필수 요건 1~4를 반영한 모양이어야 나중에 교체가 싸다.

## 필수

| | 요건 | 왜 |
|---|---|---|
| 1 | **async(파일) 전사** | 실시간 처리를 하지 않기로 확정. 회의 종료 후 배치 |
| 2 | **컨텍스트/용어 주입** | 아래 별도 항목 참조 |
| 3 | **화자 분리** (단일 혼합 스트림) | 의견의 출처를 남기기 위해. 대면 단일 마이크에서 동작해야 함 |
| 4 | **단어 또는 구간 타임스탬프** | 아래 별도 항목 참조 |
| 5 | 한국어 정확도 | — |
| 6 | 장시간 오디오 (1~2시간) | — |

## 선택

| | 요건 | 왜 |
|---|---|---|
| 7 | 음성 등록 기반 화자 식별 | 있으면 회의마다 하는 이름 매핑을 대체할 수 있다 |

## 2번(컨텍스트 주입)이 정확도 벤치마크보다 우선하는 이유

실측에서 나온 문제는 **특정 용어(제품명·전문용어)를 한 번 잘못 인식하면 회의 내내 같은 식으로 계속 틀리는 것**이었다. 그리고 컨텍스트 파라미터를 넣지 않은 상태였다. 넣지 않은 이유는 **"매번 우리 맥락에 맞춰 써서 넣는 게 번거로워서"** 였다.

그 번거로움을 없애는 것이 이 제품의 존재 이유다. 이슈 로그는 회의를 하면 자동으로 쌓이고, **그것이 곧 다음 회의의 컨텍스트다.**

```
회의 → 이슈 로그 → 다음 회의의 STT 컨텍스트 → 더 나은 회의록 → 더 나은 이슈 로그
```

이 설계에서 **로그가 쌓인 보상이 가장 빨리 돌아오는 지점**이다(회의 2회차부터). 컨텍스트 주입 기능이 없는 공급자를 고르면 이 고리가 통째로 사라진다.

**평가 시 확인할 것:**
- 자유 텍스트를 받는가, 용어 목록만 받는가 (요약 문서를 통째로 넣을 수 있어야 좋다)
- **토큰/문자 한도** — 이슈 목록을 얼마나 넣을 수 있는지를 결정한다. 참고로 이슈 200건의 한 줄 요약이 약 5,000토큰이다
- 한도 초과 시 무엇을 버릴지는 상태로 정한다: 무효를 먼저 빼고, 오래전에 결정된 것부터 요약한다

### 컨텍스트에 들어가는 것은 두 가지다

| 소스 | 성격 | 갱신 |
|---|---|---|
| **용어집** | 팀 고유명사·전문용어 | 사람이 확인하며 천천히 자람 |
| **이슈 목록** | 결정과 쟁점의 한 줄 요약 | 회의마다 자동 |

둘이 같은 한도를 나눠 쓴다. 한도가 찰 때의 우선순위는 실측으로 정하되, **출발점은 용어집 우선**이다 — 용어집은 단어 인식에 직접 작용하고 이슈 목록은 문맥 이해를 돕는 보조이기 때문이다.

## 4번(타임스탬프)을 놓치기 쉬운 이유

근거 구조가 여기 걸려 있다. 타임스탬프가 없으면 "이 결정의 근거는 회의록 어느 지점"을 가리킬 수 없고, 이슈에서 **회의록 구간**으로 내려가는 경로가 성립하지 않는다.

## 화자 이름 매핑

화자 분리는 보통 `Speaker 1`, `Speaker 2` 같은 익명 라벨만 준다. 세션마다 번호가 달라지므로 회의마다 매핑이 필요하다.

**채택안:** 회의 시작 라운드에서 각자 **이름을 말하고** 지난 회의 이후 한 일을 보고한다. 회의록에 이름이 들어가므로 발화 순서와 무관하게 매핑할 수 있고, 참가자 이름을 컨텍스트에 넣으면 이름 인식률도 함께 올라간다. 이미 하기로 한 일에 이름 한 단어를 붙이는 것이라 추가 비용이 없다.

**폴백:** 확인 화면에서 사람이 직접 지정(회의당 6클릭).

## 화자 정확도에 대한 기대치

대면·단일 마이크·6명·발화 겹침은 화자 분리에 가장 불리한 조건이다. 실제 미가공 오디오의 화자 오류율은 문헌상 10~18% 수준이며, 설정으로 없앨 수 없다.

**이 오류를 감당할 수 있게 설계돼 있다:**

- 화자는 결정에 붙지 않는다. **의견에만** 붙는다
- 의견은 목록과 확인 화면 요약에 나오지 않고 상세에만 들어간다
- 회의 직후 확인 화면에서 참석자가 함께 보므로 오귀속이 드러날 자리가 있다

정확한 화자 기록으로는 실패하는 수준이지만, **"누가 이 걱정을 했었지"를 나중에 되짚는 용도로는 충분하다.**

**가장 싼 개선책은 소프트웨어가 아니다.** 테이블 중앙의 회의용 마이크 하나가 노트북 내장 마이크보다 전사 품질과 화자 분리를 동시에 크게 개선한다.

## 공급자 평가 절차

이미 확보한 회의 녹음 파일로 후보를 같은 조건에서 비교한다.

1. 컨텍스트 없이 전사 → 기본 품질
2. **팀 용어를 컨텍스트에 넣고 전사** → 용어 고착이 사라지는지
3. 화자 분리 결과를 사람이 눈으로 검증

2번이 이 평가의 핵심이다.
