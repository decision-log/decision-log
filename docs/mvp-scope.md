# MVP 범위

## 만드는 것

> 대면 회의를 녹음해 **팀이 답해야 할 질문(이슈 후보)** 을 뽑아내는 도구.

우리 팀(6명)이 곧 사용자다. 인증·멀티테넌시·SaaS 배포는 범위 밖이다.

## 푸는 문제

| | 문제 | 어떻게 |
|---|---|---|
| 1 | 빠른 결정이 사람 머릿속에만 남는다 | 이슈 후보로 뽑아 기록 |
| 2 | 나중에 확인할 서기가 필요한데 인원이 없다 | 녹음 → 자동 추출 |
| 3 | 정리하지 않아 6명이 다르게 이해한다 | 회의 직후 같은 목록을 함께 본다 |
| 4 | AI에 매번 내용을 다시 입력해야 한다 | 나중. 기록이 비어 있으면 가치가 0이다 |

같은 팀의 나흘치 회의록을 실제로 훑은 결과가 이 문제들의 근거다. 한 질문이 나흘 동안 네 번 논의되고 네 번 미결로 남았고, 회의마다 정확히 1건씩 결정이 회의 밖으로 미뤄져 어느 것도 회수되지 않았다.

## 지금 만드는 것 — tracer bullet

한 줄이 끝까지 관통하는 가장 얇은 사슬이다. 이게 울려야 무엇을 만드는지가 눈에 보인다.

```
녹음 업로드 → 전사 → 추출 → 저장 → 화면
```

| 고리 | 무엇 |
|---|---|
| 업로드 | M4A 파일 하나. 회의 하나 = 파일 하나 |
| 전사 | OpenAI 전사 API. 25MB·25분 한도에 걸리면 ffmpeg 로 잘라 이어붙인다 |
| 추출 | 회의록을 Claude Code 에 headless 로 넘겨 이슈 후보 목록을 JSON 으로 받는다 |
| 저장 | 회의 · 회의록 · 이슈 후보. SQLite 파일 하나 |
| 화면 | 업로드 한 장 · 회의 목록 한 장 · 회의 하나의 결과 한 장 |

결과 화면의 한 줄은 **질문 + 답(있으면)** 이고, 그 아래 회의록 전문이 붙는다. 후보가 진짜인지는 회의록을 눈으로 찾아 판정한다.

처리는 동기다. 올리면 끝날 때까지 기다린다. 화자 분리는 하지 않는다. 한 줄에 화자가 없다.

## 완료 판정

실제 회의 녹음 넉 벌을 시간순으로 한 벌씩 돌린다. 한 벌마다 결과 목록을 혼자 보고 **"이 목록을 팀 앞에 띄울 수 있겠다"** 가 서면 그 벌은 통과다. 판정은 tracer bullet 이슈에 댓글로 남긴다.

판정이 서지 않으면 그 이유가 다음 작업이다. 추출 프롬프트인지, 전사 품질인지, 이슈 후보라는 단위 자체인지.

## 하지 않는 것

tracer bullet 이 울린 뒤 실제로 아쉬운 것이 나타나면 그때 연다. 미리 만들지 않는다.

| | 넣을 신호 |
|---|---|
| 후보를 사람이 확인해 이슈로 올리는 화면 | 목록을 팀 앞에 띄웠는데 버릴 것과 남길 것을 표시할 자리가 없을 때 |
| 용어집과 다음 회의 전사 컨텍스트 | 같은 용어가 회차를 넘어 같은 식으로 깨질 때 |
| 백그라운드 처리와 진행률 | 기다리는 동안 화면을 닫고 싶어질 때 |
| 근거 구간 표시 | 회의록에서 눈으로 찾는 것이 불편해질 때 |
| 화자 분리 | 누가 말했는지를 되짚고 싶어질 때 |
| MCP | 이슈가 쌓여 AI 작업이 기록과 어긋나기 시작할 때 |
