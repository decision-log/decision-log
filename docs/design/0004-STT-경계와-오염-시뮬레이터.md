# 설계 합의 — 대본이 회의록이 된다: STT 경계와 오염 시뮬레이터

대상: [decision-log/decision-log#4](https://github.com/decision-log/decision-log/issues/4)
선행: #3 오디오 잡과 재시도 (닫힘). 용어는 루트 `CONTEXT.md`, 경계 표면은 [seams.md](../seams.md) ⓵ 가 정본이다.

## 무엇이 이미 서 있었나

`SttPort` · `SimulatorSttAdapter` · 계약 테스트 스위트는 #2 걷는 뼈대가 자리만 잡아 뒀다.
이 티켓이 채우는 것은 **그 자리의 알맹이**다.

| 이미 있던 것 | 이 티켓이 하는 것 |
|---|---|
| `SttPort` 세 연산·두 레코드 | 그대로 둔다 — 부모 이슈 표면과 맞다 |
| 한도 자르기, 반영·잘린 컨텍스트 | 그대로 둔다 |
| 정방향 오염 (정답 → 오염형) | **역방향**(끌려오는말 → 정답)을 더한다 |
| 지어낸 규칙 하나 (`Caddy → 캐디`) | **실측 4벌**로 갈아끼운다 |
| 계약 테스트 3개 | 화자 라벨·타임스탬프를 더하고, 시뮬레이터 자신의 주장에 테스트를 붙인다 |
| `가짜처리` (5단계 돌다 끝남) | **회차오케스트레이터를 부르는 `회차처리`로 갈아끼운다** |

## 대본은 오디오 자리로 들어온다

**시뮬레이터는 대본을 생성자가 아니라 `Audio` 로 받는다.** 지금은 대본이 생성자 인자라 어댑터
하나가 대본 하나에 묶여 있다 — 그러면 애플리케이션에 꽂았을 때 어느 회의를 올리든 같은
회의록이 나온다. 화면에 거짓말이 뜬다.

```
업로드한 파일 = 대본(UTF-8 텍스트) → 줄 하나가 발화 하나
```

ADR 0005 가 *"CI에서 0원에 돈다 — 오디오조차 필요 없다: 가짜 STT는 대본을 받는다"* 고 한 것이
이 배선이다. 대본 파일을 올리면 사슬이 HTTP 부터 DB 까지 실제로 관통한다.

**텍스트가 아니면 실패한다.** 진짜 오디오를 올리면 UTF-8 디코딩에서 걸려 잡이 실패로 끝나고
사유가 화면에 뜬다. 바이트를 억지로 읽어 쓰레기 회의록을 만드는 것보다 낫다 —
부모 이슈 사용자 스토리 9번(*"조용히 빈 결과를 받지 않는다"*)이 요구하는 쪽이다.

**빈 전사도 실패다.** 회의록이 한 줄도 없으면 성공이 아니라 실패다. 같은 스토리의 요구다.

## 역방향 오인식

`SimulatorSttAdapter` 는 정답이 컨텍스트에 있으면 **아무 일도 하지 않았다.** 그래서 주입의
이득만 모델링되고 대가는 0으로 모델링됐다 — `stt-requirements.md` 의 공급자 평가 3번이
*"2번의 이득에서 빼야 할 값"* 이라고 부른 그 값이다.

규칙 하나가 방향 둘을 갖는다.

```
정답이 컨텍스트에 없다  →  정답 → 오염형        (고착. 이득의 반대편)
정답이 컨텍스트에 있다  →  끌려오는말 → 정답     (대가. ADR 0005 의 "응답 캐시 → 응답 Caddy")
```

한 규칙에서 두 방향이 동시에 일어나지 않는다 — 컨텍스트에 있거나 없거나 둘 중 하나다.

**빈도는 여전히 모른다.** 우리가 넣은 규칙의 함수라 순환이다(ADR 0005). 시뮬레이터가 주는 것은
*일어났을 때 시스템이 어떻게 되는지*뿐이고, 빈도는 실측이 답한다.

## 실측 규칙과 예시 규칙을 섞지 않는다

AC 가 *"상상으로 지어내면 그 순간 시뮬레이터가 우리 상상을 검증하게 된다"* 고 못박았다.

- **실측 4벌** — `스크럼 → 시끄러움`, `.git → 점기`, `.gitignore → GD 근원`,
  `툴 콜링 → 툴 풀링 / 풀 콜링 / 툴 콜딩`. 팀의 4회차분 전사본에서 나왔다. `실측오염규칙` 에 산다.
- **역방향은 실측에 없다.** 실측은 정방향만 줬다. 그래서 실측 4벌에는 끌려오는말을 채우지 않는다.
- ADR 0005 가 그림으로 든 `캐시 → Caddy` 는 **예시 규칙**이다. 실측 목록에 넣지 않고
  회차 시뮬레이터와 테스트가 자기 손으로 만들어 쓴다. 기제를 보여주는 자리이지 관측이 아니다.

### `.gitignore` 가 `.git` 보다 먼저 걸려야 한다

실측 규칙 넷 중 둘이 접두사 관계다. `.git → 점기` 가 먼저 걸리면 `.gitignore` 는
`점기ignore` 가 되어 `GD 근원` 규칙에 영영 안 걸린다. **정답이 긴 규칙부터 적용한다.**

### 흔들림은 등장할 때마다 다시 뽑는다

지금은 한 줄에 한 번만 뽑아 그 줄의 모든 등장을 같은 형태로 바꾼다. 그러면 한 줄에 두 번
나온 `툴 콜링` 이 같은 형태로 깨져 *"같은 말인지도 모른다"* 는 흔들림의 성질이 사라진다.
등장마다 뽑는다.

## 스키마 — 회의 하나 = 회의록 여러 개

seams.md ⓷ 이 요구하는 모양인데 `utterance` 의 기본키가 `(meeting_id, seq)` 라 회의당
회의록이 하나였다. `transcript` 를 두고 발화를 거기 매단다.

```sql
create table transcript (
    id         uuid primary key,
    meeting_id uuid not null references meeting(id),
    seq        int  not null,          -- 회의 안에서 몇 번째 덩이인가. 합칠 때 이 순서다
    created_at timestamptz not null default now(),
    unique (meeting_id, seq)
);
-- utterance.meeting_id → utterance.transcript_id, 기본키 (transcript_id, seq)
```

**여러 개인 이유는 벌(vintage)이 아니라 덩이다.** 대기가 길면 사람이 논의를 두 덩이로 끊는다
(seams.md ⓷). 여러 벌을 나란히 두고 판정하는 것은 추출 결과 쪽 이야기이고 #18 의 몫이다.

`회의록저장` 은 **덧붙인다** — 부르면 다음 seq 로 회의록 한 벌이 생긴다. 회의당 잡이 하나이고
일꾼도 하나라 seq 계산에 경쟁이 없다.

**v0.5 화면은 1:1 로만 쓴다.** 덩이를 나누는 버튼은 이 티켓에 없다.

## 미룬 충돌 — `돈다()` 가 회의를 안 만든다

#3 합의문이 *"진짜 연결 티켓에서 `돈다()` 가 회의ID를 받도록 고쳐야 한다"* 로 미뤄 둔 것이다.
사람이 회의를 먼저 만들고 오디오를 올리는데 `돈다()` 는 자기가 또 만들고 있었다.

```
돈다(회의ID, Audio, 프롬프트버전)     ← 회의를 만드는 것은 호출자의 일이다
```

`회의저장소.새회의()` 는 포트에 남긴다 — 회차 시뮬레이터가 회의를 만들 길이 필요하다.
`meeting.title` · `held_on` 의 기본값도 그래서 남긴다. 그 둘이 사라지는 것은 `새회의()` 를
쓰는 마지막 호출자가 사라질 때다.

### 전사와 추출이 갈린다

`회차처리` 가 전사와 추출 사이에서 진행을 보고해야 하므로 오케스트레이터가 둘 사이에서
제어를 돌려줘야 한다.

```
전사한다(회의ID, Audio)        → 전사결과
추출한다(전사결과, 프롬프트버전) → 회차결과
돈다(...)                      = 위 둘의 합성. 회차 시뮬레이터가 쓴다
```

**이 티켓은 `전사한다` 까지만 잡에 잇는다.** 추출 경계는 #5 의 산출물이다 — #5 가
`회차처리` 에 `추출한다` 를 덧붙이고 진행을 2단계로 늘린다.

다만 오케스트레이터 생성자가 `ExtractPort` 를 요구하므로 빈은 지금 꽂는다
(`MarkerExtractAdapter`). 프로덕션 경로에서 불리지 않는다.

## 잡에 꽂는 것

`가짜처리` 를 지우고 `회차처리` 를 꽂는다. 가짜의 javadoc 이 *"진짜가 붙기 전까지 자리를
지키는"* 것이라고 스스로 밝혔고, 남겨 두면 통합 테스트가 진짜 경로 대신 가짜를 계속 잰다.

- 진행은 **1단계** — 전사 하나뿐이다. `진행(0,1)` → 전사 → `진행(1,1)`.
- `fail` 파일명 규칙도 함께 사라진다. 실패 시연은 **텍스트가 아닌 파일 업로드**가 맡는다.
  진짜 실패 경로라 가짜보다 낫다.
- `dl.processing.step-millis` 는 의미를 잃어 지우고 `dl.stt.simulator.seed` 가 대신 선다.
  프롬프트 버전은 추출이 붙는 #5 가 가져온다 — 지금 두면 안 쓰는 설정이 하나 는다.

## 계약과 테스트

**계약 테스트**(어댑터 세 벌 전부 통과):

- 화자 라벨은 optional 이다 — **null 이거나 비어있지 않다.** `"화자?"` 같은 자리 채우기가
  걸린다. 시뮬레이터는 화자 분리를 하지 않으므로 null 을 준다.
- 타임스탬프는 구간이다 — `시작 ≤ 끝`, 구간은 앞으로만 간다.
- (기존) 결과가 나온다 / 컨텍스트가 조용히 사라지지 않는다 / 원본응답을 보관한다.

**시뮬레이터 자신의 주장**(계약이 아니다 — 진짜 어댑터는 이걸 못 지킨다):

- 시드를 고정하면 같은 대본·같은 컨텍스트에 같은 회의록이 나온다.
- 컨텍스트에 용어를 넣으면 회의록이 달라진다 (정방향이 사라진다).
- 정답이 컨텍스트에 있으면 끌려오는말이 정답으로 끌려간다 (역방향이 나타난다).
- 일관은 한 회차 안에서 같은 형태, 흔들림은 여러 형태로 깨진다.
- `.gitignore` 가 `.git` 규칙에 먼저 먹히지 않는다.
- 텍스트가 아닌 오디오는 실패한다.

**통합 테스트**: 대본 파일을 올리면 잡이 완료에 도달하고 `transcript` 와 `utterance` 에 행이
남는다. 용어집을 채운 뒤 올리면 그 용어가 안 깨진 회의록이 저장된다 — **컨텍스트가 경계를
넘어갔다는 것이 DB 에서 보인다.** 텍스트가 아닌 파일은 실패하고 재시도해도 다시 실패한다.

## 이 이슈에서 안 하는 것

- **진짜 공급자 어댑터와 재생 어댑터** — #7. `OpenAiSttAdapter` 는 #2 가 세워둔 자리 그대로 둔다.
- **`작업상태` 폴링** — 시뮬레이터는 동기라 `전사요청` 이 돌아온 시점에 이미 완료다.
  진짜 비동기 공급자가 오는 #7 이 폴링과 청크 진행 보고를 정한다. 그때까지 `작업상태` 의
  `Running(완료청크, 전체청크)` 는 소비자가 없다.
- **`PROMPT_CHAR_BUDGET` 의 실제 값** — 추측치로 남는다. 공급자 평가 절차 1·2번이 답한다.
- **추출을 잡에 잇기** — #5.
- **회의록이 이미 있으면 전사를 건너뛰기** — #3 합의문이 처리 구현의 몫으로 넘긴 절약인데,
  재처리(#18)가 *"확인 전이면 같은 오디오로 다시 처리"* 를 요구하므로 건너뛰기 규칙이
  재처리 의미와 엉킨다. 진짜 전사가 붙어 비용이 실제로 발생하는 #7 에서 함께 정한다.
- **회의록 덩이 나누기 버튼** — 스키마만 받고 화면은 1:1 이다.
- **여러 벌 비교와 현재 벌 포인터** — #8 · #18.
