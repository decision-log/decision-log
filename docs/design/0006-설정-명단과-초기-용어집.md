# 설계 합의 — 설정: 참가자 명단과 초기 용어집

대상: [decision-log/decision-log#6](https://github.com/decision-log/decision-log/issues/6)
선행: #2 걷는 뼈대 (닫힘). 그릴링 세션에서 합의된 내용이며, 용어는 루트 `CONTEXT.md`를 따른다.

## 절단면

**수직 슬라이스** — 화면부터 REST API, 도메인, DB까지 한 번에 관통한다. 이 이슈를 앞으로 당긴 이유가 "1회차 전에 명단이 있어야 한다"인데 화면 없는 명단은 팀이 못 넣고, 설정 화면은 목록을 보여주고 고치는 가장 단순한 화면이라 첫 화면의 기반 비용(API 호출 방식, 테스트 패턴)을 치르기에 제일 싼 자리다.

## 참가자 명단

- **추가 · 삭제 · 이름 고치기 전부 허용.** 중복 이름만 막는다. 용어집에서 삭제를 막은 이유("이력이 붙는 순간 추적 대상이 된다")는 명단에 적용될 자리가 없다 — 이 범위에서 명단을 참조하는 것이 없다(화자 매핑 범위 밖, 회의 생성도 이 이슈엔 없다).
- **저장은 목록 통째 교체.** `명단저장(이름 목록)` + `명단()` 두 연산. 추가·삭제·이름 고치기가 전부 "고친 목록을 저장" 하나로 수렴한다. 저장소 계약의 "쓰기는 묶음으로" 방침과 맞는다.
- 순서는 의미를 갖지 않는다. 명단은 컨텍스트 우선순위 1순위라 잘릴 일이 없다.

## 초기 용어집 붙여넣기

- 팀이 가진 용어 목록의 실물은 **아직 없다** — 형식은 우리가 정하고 팀이 맞춘다. 재료는 #1의 4회차분 회의록 실측.
- **형식: 한 줄에 항목 하나. 줄 안의 첫 탭 또는 첫 콜론이 표기/뜻 경계.** 구분자 없는 줄은 표기만 등록한다. 스프레드시트 복사(탭)와 손 타이핑(`표기: 뜻`)을 둘 다 받는다. 콜론 든 표기가 잘못 쪼개지는 드문 경우는 붙여넣은 뒤 수정으로 구제한다.
- **이미 있는 표기는 무시한다** — 기존 `용어집저장소.추가` 계약 그대로. 두 번 붙여넣어도 결과가 같고, 나중에 확인 화면을 거쳐 들어온 항목(뜻이 회의록 인용인 것)을 손으로 쓴 목록이 덮는 통로를 만들지 않는다. 같은 붙여넣기 안의 중복 표기도 같은 규칙 — 먼저 나온 줄이 이긴다.
- 붙여넣기는 확인(승격)을 거치지 않고 바로 용어집에 들어간다. 이슈 본문이 명시한 동작이다.

## 항목 수정

- **표기와 뜻 둘 다 고칠 수 있다. 뜻 비우기도 허용.** 컨텍스트로 나가는 건 표기만이 아니라 뜻도인데, 삭제가 없는 마당에 뜻을 못 고치면 오타 난 뜻에 출구가 없다. "뜻은 회의록에서 인용하지 작문하지 않는다"는 원칙은 추출→확인 사슬의 이야기이며, 붙여넣기로 들어온 뜻은 애초에 사람이 쓴 것이라 고치는 것도 같은 급이다.
- **표기 수정 충돌은 거부.** 표기 A를 B로 고치는데 B가 이미 있으면 에러. 병합은 삭제의 다른 얼굴이고 삭제는 이 이슈가 만들지 않는다.
- 수정은 제자리 교체다. 이력은 남기지 않는다 — 수용 기준 그대로.

## 계약과 스키마

`저장소`(도메인 포트)에 추가:

```java
interface 명단저장소 {
    void 명단저장(List<String> 이름들);   // 통째 교체
    List<String> 명단();
}
```

`용어집저장소`에 추가:

```java
void 수정(String 기존표기, String 새표기, String 새뜻);  // 새표기 충돌 시 거부
```

마이그레이션:

```sql
create table participant (
    name text primary key
);
```

`glossary` 테이블은 그대로 쓴다. 붙여넣기 파서(텍스트 → 용어 목록)는 **결정적 변환이므로 도메인 모듈에** 두고, 프레임워크 없이 테이블 단위 테스트로 돈다.

## 화면

- **설정 한 장, 두 섹션** — 명단 / 용어집.
- 명단: 목록 편집 후 저장.
- 용어집: 전량 목록 + 항목 인라인 수정, 붙여넣기 텍스트 영역. 미리보기 단계는 없고 넣은 뒤 "N개 추가, M개 무시(이미 있음)" 요약으로 대신한다.
- 화면 라우팅은 깔지 않는다 — 화면이 하나뿐인데 라우터를 깔면 추측이다. 다음 화면 이슈(#9, #10)가 올 때 정한다.

## 테스트

- 붙여넣기 파서: 테이블 단위 테스트 (구분자 세 경우, 뜻 없는 줄, 중복 줄, 빈 줄).
- 명단·용어집 저장소: 걷는뼈대 통합 테스트 패턴으로 (중복 무시, 통째 교체, 수정 충돌 거부 포함).
- 화면 테스트 1개: 붙여넣기 흐름.

## 이 이슈에서 안 하는 것

이슈 수용 기준 그대로 — 용어집 항목 삭제, 용어 간 관계·계층, 정의 이력, 직무 공통 용어 미리 심기. 추가로: 화면 라우팅, 회의 생성·참가자 연결, 표기 병합.
