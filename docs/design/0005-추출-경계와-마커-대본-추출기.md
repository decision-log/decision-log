# 설계 합의 — 회의록이 후보가 된다: 추출 경계와 마커 대본 추출기

대상: [decision-log/decision-log#5](https://github.com/decision-log/decision-log/issues/5)
선행: #4 대본이 회의록이 된다 (닫힘). 용어는 루트 `CONTEXT.md`, 경계 표면은 [seams.md](../seams.md) ⓶ 가 정본이다.

이슈 본문의 AC 와 코멘트 둘(*"#2 가 이 티켓의 계약을 일부만 만들어놨다"*, *"본문의 AC 를 그릴링
결과로 갈아끼웠다"*)에서 이미 결론난 것은 여기서 다시 다루지 않는다. 이 문서는 그 뒤에
**남아 있던 갈림길**을 적는다.

## 무엇이 이미 서 있었나

| 이미 있던 것 | 이 티켓이 하는 것 |
|---|---|
| `ExtractPort` 두 레코드 (`이슈후보초안` 포함) | 표면을 다시 세운다 — `초안` 은 `CONTEXT.md` 금지어다 |
| `MarkerExtractAdapter` (이슈·용어 둘) | 종류 열, 스위치 넷, 로컬키, 메타 |
| `issue_candidate` 한 장 | 벌 · 의견 · 할일 · 용어후보 · 근거 |
| 대본 두 벌 (시뮬레이터 · 통합테스트에 각각 인라인) | **리소스 파일 한 벌** |
| `회차처리` 1단계 (전사) | 2단계 (전사 · 추출) |
| 계약 테스트 없음 | 계약 여섯 + 그 계약이 잡는지 재는 대각선 |

## 포트와 저장을 두 겹으로 가른다 — 내용만 공유한다

AC 둘이 서로 당긴다. *"필드는 한 군데만 정의된다 — 포트와 저장이 같은 `…내용` 레코드를 쓴다"* 와
*"로컬키는 후보 ID 로, 전역 구간 번호는 `(회의록, 순번)` 으로 저장 시 한 번 해소한다."*

**층마다 타입이 다른 필드가 둘이다.** `이슈후보참조` 는 포트에서 로컬키, 저장에서 후보ID 다.
근거구간은 포트에서 전역 번호, 저장에서 `(회의록, 순번)` 이다. 그래서 레코드를 글자 그대로
공유하면 저장 코드가 **절대 안 쓸 필드**를 들고 다니게 되고, DB 에서 읽어 되만들 때 그 자리에
무엇을 넣을지가 애매해진다 — 이미 죽은 값이다.

→ **내용 레코드에서 참조와 구간을 빼낸다.** 층이 다른 것은 바깥에, 층이 같은 것만 안에.

```java
// 도메인 — 저장되는 것
record Extraction(ExtractionId id, MeetingId meeting, Meta meta, Instant createdAt,
                  List<IssueCandidate> issueCandidates, List<Opinion> opinions,
                  List<Task> tasks, List<TermCandidate> termCandidates) {}

record IssueCandidate(CandidateId id, ExtractionId extraction, Content content,
                      List<Evidence> evidence) {
    record Content(String question, ProposedState state, String answer, String undecidedReason) {}
}
record Opinion(OpinionId id, ExtractionId extraction, CandidateId issue /*null 가능*/,
               Content content, Evidence evidence) {
    record Content(String speakerLabel, String text) {}
}
record Task(TaskId id, ExtractionId extraction, CandidateId issue /*null 가능*/,
            Content content, Evidence evidence) {
    record Content(String text, String assignee) {}
}
record TermCandidate(TermCandidateId id, ExtractionId extraction, Content content,
                     List<Evidence> evidence) {
    record Content(String spelling, String meaning) {}
}
record Evidence(TranscriptId transcript, int seq) {}
enum ProposedState { 쟁점, 결정 }
```

```java
// 포트 — 경계를 넘는 것
interface ExtractPort {
    ExtractionResult extract(List<Utterance> transcript, String promptVersion);

    record LocalKey(String value) {}
    record ExtractionResult(Meta meta,
                            List<ExtractedCandidate> issueCandidates,
                            List<ExtractedOpinion> opinions,
                            List<ExtractedTask> tasks,
                            List<ExtractedTerm> termCandidates) {}
    record ExtractedCandidate(LocalKey key, IssueCandidate.Content content, List<Integer> spans) {}
    record ExtractedOpinion(LocalKey issueRef /*null 가능*/, Opinion.Content content, int span) {}
    record ExtractedTask(LocalKey issueRef /*null 가능*/, Task.Content content, int span) {}
    record ExtractedTerm(TermCandidate.Content content, List<Integer> spans) {}
}
record Meta(String modelName, String promptVersion, String promptHash, TokenUsage tokens /*null 가능*/) {}
record TokenUsage(long input, long output, long cacheHit) {}
```

**`Extracted` 접두어를 붙이는 이유** — `RoundOrchestrator.extract()` 가 두 층의 레코드를 한
파일에서 쓴다. 포트 쪽을 `Opinion` 으로 짧게 두면 한 줄에 `Opinion` 이 두 뜻으로 나오고
정규화 이름을 써야 한다. 이름이 층을 말해 주는 쪽을 고른다.

**의견·할 일의 근거가 단수인 것은 표면 그대로다.** `seams.md` ⓶ 이 이슈후보·용어후보만
`근거구간[]` 으로 적었다. 단수면 `근거 비지 않음` 이 not-null 하나로 강제된다.

## 엄격한 생성자와 관대한 입구가 둘 다 필요하다

AC 가 *"생성 시점에 강제된다"* 와 *"어댑터가 위반 입력을 받으면 버리지 않고 쟁점으로 강등한다"*
를 동시에 요구한다. 관대한 입구가 어디 사느냐가 문제였다.

**도메인이 포트 결과를 받아 정규화하는 안은 못 쓴다.** 계약이 어댑터가 아니라 `ExtractPort` 에
걸리기로 했으므로 포트를 넘는 순간 여섯 불변식이 이미 참이어야 한다. 정규화를 포트 바깥에 두면
계약 테스트가 어댑터가 아니라 정규화기를 재게 되고, #8 의 진짜 어댑터는 계약을 안 지켜도
초록불이 뜬다.

**어댑터마다 자기 손으로 하는 안도 안 된다.** 위반을 무엇으로 바꿀지는 도메인 규칙이다.
어댑터는 위반을 *만들어내는* 방식만 다르다 — 마커는 대본 스위치로, #8 의 진짜는 LLM 이 뱉은
JSON 으로.

→ **엄격한 생성자 옆에 관대한 팩토리를 둔다.** 어댑터 셋이 전부 그걸 부른다.

```java
record Content(String question, ProposedState state, String answer, String undecidedReason) {
    Content { /* 위반이면 IllegalArgumentException — 도메인 내부 경로를 지킨다 */ }

    /** 추출기가 쓰는 입구 — 버리지 않고 맞춘다. */
    static Content lenient(String question, ProposedState state, String answer, String reason) { … }
}
```

어댑터가 `lenient` 를 안 부르고 생성자를 직접 쓰면 터진다. 조용하지 않으므로 받아들인다.

### 답이 상태를 정한다

AC 는 `결정 + 답 없음` 만 말했다. 반대 방향(`쟁점 + 답 있음`)이 안 정해져 있었다.

→ **답이 이긴다.** `상태 = 답이 있으면 결정, 없으면 쟁점`. 미결정사유는 결과가 쟁점일 때만 남는다.

| 들어온 것 | 나가는 것 | |
|---|---|---|
| 결정 + 답없음 | 쟁점 | AC 그대로 |
| 결정 + 답없음 + 사유 | 쟁점 + 사유 | 사유가 산다 |
| 쟁점 + 답있음 | **결정 + 답** | 답이 산다 |
| 결정 + 답있음 + 사유 | 결정 + 답 | 사유만 버린다 |

상태를 살리고 답을 버리면 그게 **누락**이다 — *"과잉추출은 사람이 5초에 버리지만 누락은 영원히
모른다."* 반대로 `결정` 으로 올리는 것은 과잉이고, #10 의 확인 1장에 *"각 이슈가 쟁점인지
결정인지 고친다"* 가 이미 있어 클릭 한 번에 되돌아온다.

ADR 0002(*AI 는 이슈를 결정하지 못한다*)와 안 부딪힌다. 추출은 상태를 **제안**할 뿐이고 후보는
추적 대상이 아니다. 잃는 것은 `결정` 에 붙어 온 미결정사유 하나뿐인데, 그것은 *"답이 없는 이유"*
라 답과 원리적으로 공존할 수 없다.

### 근거가 비면 터진다

이것만 관대한 팩토리가 못 구제한다. 없는 것을 지어낼 수 없고 *"전체 회의록"* 을 근거로 붙이는
것은 거짓말이다. 그리고 AC 가 근거의 존재 이유를 이미 적었다 — *"없으면 '깨진 표기 옆에 그 말이
나온 회의록 한 줄' 이 원리적으로 불가능하다."* 근거 없는 후보는 확인 화면에서 사람이 판단할
재료가 0 인 항목이다.

→ **포트 레코드 생성자가 거부한다.** 잡이 실패로 끝나고 사유가 화면에 뜬다. #4 가 `전사 결과가
비었다` 와 `텍스트가 아니면 실패한다` 에 쓴 논리와 같은 자리다.

마커 추출기는 이걸 **원리적으로 못 만든다** — 마커가 박힌 발화 번호가 곧 근거다.
**이 결정이 뒤집히는 자리는 #8 이다.** LLM 이 근거를 한 건 빼먹으면 회의 하나가 통째로 실패한다.

## 추출은 회의ID 만 받는다

AC 가 *"추출은 회의에 붙는다. 회의록이 여러 개면 전체를 합쳐 추출이 한 번 돈다"* 와 *"전역 구간
번호는 `(회의록, 순번)` 으로 해소한다"* 를 함께 요구하는데, `추출한다(전사결과, …)` 가 받던
`전사결과` 에는 **회의록 ID 도 덩이 경계도 없었다.** 전역 17 번이 어느 회의록의 몇 번인지 되돌릴
재료가 통째로 없고, 회의를 두 덩이로 끊으면 뒷덩이만 추출된다.

```
전사한다(회의ID, Audio)          → 회의록 ID          한 벌을 덧붙인다
추출한다(회의ID, 프롬프트버전)     → 회차결과           회의록 전량을 읽어 이어붙인다
돈다(회의ID, Audio, 프롬프트버전)  = 위 둘의 합성
```

```
[t0#0 t0#1 t0#2 | t1#0 t1#1]      이어붙인 순서가 곧 전역 번호다
   0    1    2      3    4        전역 3 → Evidence(t1, 0)
```

**저장된 것이 정본이 된다.** 왕복 한 번이 늘지만 6명 규모에서 잴 수 없고, 잡이 추출만 다시 돌
때도 같은 길이다. `회의저장소` 에 `회의록전량(회의ID)` 이 서고 `회의록저장` 은 만든 ID 를 돌려준다.

## 저장 — 벌 하나가 한 단위다

**`ExtractionStore` 를 새로 세운다.** `IssueStore` 는 이슈의 저장소이고 이슈는 추적 대상인데,
후보·의견·할 일·용어후보는 넷 다 추적 대상이 아니다 — `CONTEXT.md` 가 만든 그 구분이 포트 경계와
그대로 맞는다. `promote` 만 `IssueStore` 에 남는다. 이슈를 **만드는** 일이라서다.

```java
interface ExtractionStore {
    /** 벌 하나를 통째로. 회의의 현재 벌 포인터도 여기서 옮긴다. */
    void save(Extraction extraction);

    /** 현재 벌의 미확인 후보만. */
    List<IssueCandidate> unconfirmedCandidates(MeetingId meeting);

    /** 현재 벌의 용어 후보. #11 이 쓴다. */
    List<TermCandidate> termCandidates(MeetingId meeting);
}
```

**`미확인후보` 가 현재 벌만 주는 것이 이 티켓에서 새로 생긴 요구다.** 지금은 그 회의의 모든 후보를
주는데, 벌이 셋 병존하면 같은 회의록에서 뽑은 후보가 3배로 뜨고 #14 의 컨텍스트 조립에도 3배로
들어간다. 조용히 깨지는 자리라 벌을 도입하는 이 티켓이 함께 막는다.

`issue_candidate` 는 `meeting_id` 를 **안 갖는다.** `extraction` 경유 조인 하나가 두 경로가
어긋나는 것보다 싸다.

### 근거는 테이블 둘 + 인라인 둘

티켓의 미정 항목(*"소유자별 테이블 넷이냐 다형 한 장이냐"*)은 전제가 하나 어긋나 있었다.
소유자가 넷이 아니라 **둘**이다 — 의견과 할 일의 근거는 표면상 단수다.

```sql
create table issue_candidate_evidence (
    candidate_id  uuid not null references issue_candidate(id),
    transcript_id uuid not null,
    seq           int  not null,
    primary key (candidate_id, transcript_id, seq),
    foreign key (transcript_id, seq) references utterance(transcript_id, seq)
);
create table term_candidate_evidence ( … 같은 모양 … );

create table opinion (
    …,
    evidence_transcript uuid not null,
    evidence_seq        int  not null,
    foreign key (evidence_transcript, evidence_seq) references utterance(transcript_id, seq)
);
```

`(transcript_id, seq)` 가 마침 `utterance` 의 기본키다. 근거를 거기에 FK 로 걸면 계약 ③
**`구간범위`** 를 DB 가 함께 지킨다 — 없는 발화를 가리키는 근거가 원리적으로 안 들어간다.

**다형 한 장을 안 쓰는 이유**는 `owner_id` 에 FK 를 못 걸어 고아가 조용히 생기고 `owner_kind`
오타가 컴파일에서 안 잡히기 때문이다. `stack.md` 가 *"스키마가 정본이고 코드가 파생물이어야
스키마가 움직여도 컴파일에서 잡힌다"* 를 ORM 을 안 쓰는 이유로 든 그 자리를 정확히 되돌린다.

의견이 실제로 여러 발화에 걸치면 그때 테이블을 만든다.

### 후보는 새 이슈 ID 를 받는다

AC 는 타입만 갈랐다(`후보ID ≠ 이슈ID`). 값까지 가른다.

`issue_candidate.promoted` 불리언을 **`promoted_issue_id`** 로 바꾼다. 확인됐는지(null 여부)와
어느 이슈가 됐는지를 한 컬럼이 답한다. #17 이 *"이번에 뽑힌 후보를 **기존 이슈**에 연결한다"* 를
요구하는데 거기서는 두 ID 가 같을 수가 없으므로, 그때 이 컬럼에 기존 이슈 ID 를 넣는 것으로
끝난다 — 스키마 변경이 없다.

그리고 값이 안 겹치면 문자열로 왕복하는 경계(HTTP·JSON)에서 둘을 바꿔 넣어도 조회가 **빈다.**
타입만 가르면 컴파일러는 막지만 그 경계는 못 막는다.

승격은 CTE 한 문장으로 남는다 — 후보가 자바를 왕복하지 않는다는 성질은 그대로다.

### `V1` 을 다시 깐다

AC 가 *"`V1__baseline.sql` 을 제자리에서 고친다"* 고 했는데, 지금 마이그레이션이 다섯 장이고
뒤쪽 둘이 `V1` 을 되돌리고 있다. `V4` 는 `utterance.meeting_id` 를 떼고 `V5` 는 `glossary` 의
한글 컬럼을 바꾼다. `V1` 을 고치면 `V4` 가 없는 컬럼을 `drop` 하려 든다 — *"`V1` 만 고치고
나머지는 둔다"* 가 성립하지 않는다.

→ **`V2`~`V5` 를 `V1` 에 접어 넣고 파일을 지운다.** 데이터가 아직 없으니 지금만 공짜고,
`baseline` 이 그제서야 이름값을 한다 — 동결선 전에는 마이그레이션이 아니라 **스키마 정의**다.
`V3`·`V4` 주석의 설계 기록은 `V1` 로 옮긴다.

동결선과 그 이유를 `V1` 첫머리에 적는다.

> **동결선: 첫 확인.** 팀이 회의에서 후보를 이슈로 올리는 순간부터 되살릴 수 없는 데이터가
> 생긴다. 그 전에는 이 파일을 고치고, 그 뒤로는 `V2` 부터 더한다.

대가는 둘 — 개발 DB 와 compose 볼륨을 한 번 날려야 하고, *"무엇이 언제 왜 추가됐나"* 가 파일
경계 대신 커밋 로그와 주석에만 남는다.

## 마커 대본

**정답은 발화와 같은 줄에 있어야 한다.** 코멘트 §3 이 *"제목에 깨진 표기가 박히는 것은
`SimulatorSttAdapter` 가 이미 낸다 — `line.replace()` 가 마커 내부까지 치기 때문"* 이라고 했고,
그게 *"가장 값진 테스트"* 를 떠받치는 기제다. 대본 아래에 따로 정답 블록을 두면 오염이 못 친다.

**같은 줄 안에서는 뒤에 모은다.** 왼쪽은 사람이 말한 문장, `|` 오른쪽은 정답. 마커가 담을 것이
많아졌는데(종류 열, 로컬키, 둘째값) 그게 문장 중간에 박히면 대본을 눈으로 못 읽는다. 대본은
사람이 읽고 고치라고 있는 물건이다.

**줄바꿈은 못 쓴다.** `script()` 가 `text.lines()` 로 자르므로 줄 하나가 발화 하나다(#4).
마커를 다음 줄에 두면 별개 발화가 된다. 한 줄이 길어지는 값을 치른다.

```
# 마커  종류[@키]: 본문 [= 둘째값]
# 종류  이슈 · 답 · 사유 · 의견 · 할일 · 용어 ┆ 분할 · 작문 · 누락 · 무담당

리버스 프록시는 Caddy로 가죠 | 이슈@proxy: 리버스 프록시를 무엇으로 할 것인가 | 분할@proxy: 어느 리버스 프록시를 쓸 것인가 | 작문@proxy: 배포를 어떻게 할 것인가 | 용어: Caddy = 자동 HTTPS 되는 리버스 프록시
나는 nginx가 익숙한데 | 의견@proxy: nginx가 익숙하다
그럼 Caddy로 갑시다 | 답@proxy: Caddy | 할일@proxy: 리버스 프록시 설정 = 가영 | 무담당@proxy
매일 아침 스크럼은 계속 합시다 | 이슈@proxy: | 용어: 스크럼
```

- 본문 없는 `이슈@키` 는 **근거만 더한다.** 같은 이슈가 여러 줄에 걸치는 자리다
- `무담당@키` 는 **같은 줄의 할 일**에 적용된다
- `의견` 에 `@키` 가 없으면 **무소속**이다
- 용어는 키가 없다 — 표기가 열쇠다

**대본은 리소스 파일 한 벌이고 읽는 자리도 하나다.** 지금 회차 시뮬레이터와 통합 테스트에 각각
인라인으로 박혀 두 벌로 갈라져 있는 것이 AC 가 지목한 상태다.
→ `adapters-fake/src/main/resources/dl/script/default.txt`, `Scripts.defaultScript()`.

### 스위치 넷은 마커 종류다

표식(`이슈+@키` · `이슈~@키`)으로 두면 코멘트 §4 의 시그니처 표를 만들 수 없다. 과잉분할이 이슈
4 건을 전부 쪼개 8 이 되고 그중 3 건이 작문오염 대상이려면 **같은 이슈가 두 스위치의 대상**이어야
하는데, `+` 와 `~` 가 둘 다 `= 둘째값` 을 써서 한 자리를 다툰다.

→ **분할 · 작문 · 누락 · 무담당을 마커 종류로 만든다.** 한 이슈에 몇 개든 붙고 각자 자기 둘째값을
갖는다. 대본만 보고 스위치별 결과를 예측할 수 있다.

넷 다 대본이 지정한다. *"과잉분할은 전부 쪼갠다"* 로 두면 쪼갠 제목을 어댑터가 지어내게 되는데,
그것은 *"대본에 정답을 미리 달아두고 읽는다"* 는 이 티켓의 근본과 반대다. 확률이 아닌 이유는
코멘트 §4 가 이미 적었다.

**스위치는 어댑터 생성자로만 켠다.** 애플리케이션 설정은 안 만든다 — #4 가 `dl.processing.step-millis`
를 지운 이유 그대로, 소비자 없는 설정을 안 늘린다. 애플리케이션에는 스위치 없는 마커가 꽂히고,
회차 시뮬레이터와 테스트만 생성자로 켠다.

### 마커의 프롬프트 해시는 스위치 조합의 해시다

`토큰수` 는 비운다(모델을 안 부른다). `모델명` 은 `marker` — 이 결과를 만든 것의 진짜 이름이다.
남는 것이 `프롬프트해시` 인데 마커에는 프롬프트가 없다. 지금 코드는 `"v" + 프롬프트버전` 을 그
자리에 넣는데 해시가 아니다.

해시의 용도가 *"한 회의에 여러 벌을 나란히 놓고 판정한다"* 라 상수가 들어가면 세 벌이 전부 같은
해시로 뜬다.

→ **`sha256("marker:" + 정렬된 스위치 이름)`.** 마커에서 결과를 바꾸는 유일한 설정이 스위치이고,
진짜 어댑터에서 그 자리를 차지하는 것이 프롬프트 파일이다. 둘 다 *"이 벌을 만든 설정의 지문"* 이다.

### 그 밖의 마커 규칙

- **참조가 안 풀리면 무소속으로 만든다.** 의견을 버리지도 이슈 후보를 지어내지도 않는다 —
  `이슈후보참조` 가 optional 인 이유가 그것이고, 그래야 계약 ①이 참이 되면서 개수가 안 준다.
  누락 스위치로 이슈가 빠질 때 그 이슈를 참조하던 의견이 지나는 길이 이 길이다
- **용어후보 병합은 표기 문자열 그대로 비교한다.** 대소문자·공백을 정규화하지 않는다 —
  `툴 풀링` 과 `툴 콜링` 이 다른 것으로 남아야 흔들림이 보인다. 뜻은 먼저 나온 것이 이긴다.
  병합도 `lenient` 와 같은 자리(도메인 공용 함수)에 산다
- **화자 라벨은 항상 `null`.** 시뮬레이터 STT 가 화자 분리를 안 하고 이번 범위에 소비자도 없다

## 재시도는 전사를 건너뛴다

추출을 이으면 없던 경로가 생긴다.

```
업로드 → 전사 ✓ (회의록 0번) → 추출 ✗
재시도 → 전사 ✓ (회의록 1번 덧붙음) → 추출 ✓
                              ↑ 합쳐서 한 번 도니 같은 회의가 두 번 들어간다
```

이슈가 정확히 두 배로 뽑히고 **에러는 안 난다.** `JobRunner` 의 재시도가 같은 잡 행을 리셋해
`process()` 를 처음부터 다시 돌리고 `회의록저장` 은 덧붙이기 때문이다.

*"재시도할 때 회의록을 지운다"* 는 못 한다 — 이전 벌의 근거가 `utterance(transcript_id, seq)` 로
FK 를 걸고 있어 DB 가 막는다. 오히려 그 FK 가 이 실수를 잡는다.

→ **회의록이 이미 있으면 전사를 건너뛴다.** #4 합의문이 이걸 *"재처리(#18)의 의미와 엉킨다"* 며
#7 로 미뤘는데 그 엉킴이 여기서 풀린다. **잡 재시도와 재처리는 다른 연산이다** — 재시도는 실패한
지점부터 이어 가는 것이고, *"같은 오디오로 공급자를 바꿔 다시"* 는 #18 이 만들 명시적 버튼이다.
덤으로 진짜 STT 가 붙었을 때 실패 한 번이 전사 비용을 두 번 물리지 않는다.

`회차처리` 는 2단계가 된다. `진행(0,2)` → 전사 → `진행(1,2)` → 추출 → `진행(2,2)`.
`dl.extract.prompt-version` 이 여기서 선다(#4 가 #5 로 미룬 것).

## 계약 여섯과, 그 계약이 잡는지 재는 대각선

이 티켓의 구현체는 **마커 하나**고 마커는 여섯을 다 지킨다. 계약 스위트가 전부 초록불인데
**검사가 작동해서 초록인지 검사가 비어서 초록인지 구분이 안 된다.**

코멘트 §5 가 어댑터 아홉 벌로 대각선을 이미 확인했지만 **그 실험이 레포에 안 남아 있다.**
남기지 않으면 #8 이 한 번도 검증된 적 없는 스위트에 기대게 되고, 그건 이 저장소가 반복해서
거부해 온 조용한 자리다.

→ **검사 여섯을 함수로 빼고, 위반 어댑터 여섯이 자기 불변식에서만 떨어지는 것을 같은 함수로
잰다.** 위반 어댑터는 마커 결과 하나를 놓고 필드 한 군데씩 망가뜨리는 것이라 싸다.

```
계약 ① 참조무결성  ② 로컬키유일  ③ 구간범위  ④ 용어표기유일  ⑤ 메타정직  ⑥ 상태·답정합
위반   참조끊김 · 로컬키중복 · 구간범위밖 · 용어중복 · 토큰부분채움 · 결정인데답없음
```

**결정성 · 대본전량 · 스위치시그니처는 계약에 안 들어간다**(AC). 마커 전용 테스트에 둔다.

계약 검사·계약 테스트·대각선·마커 전용 테스트 넷 다 `adapters-real/src/test/java/dl/adapters/extract/`
에 산다 — STT 선례 그대로다.

**통합 테스트**: 대본을 올리면 `extraction` · 후보 · 의견 · 할 일 · 용어후보 · 근거에 행이 남고
`meeting.current_extraction_id` 가 채워진다. 잡을 재시도해도 회의록이 늘지 않는다.

## 회차 시뮬레이터는 스위치를 받아 도는 데까지

`RoundSimulator` 는 포트가 바뀌고 대본이 리소스로 나가면서 어차피 손을 대야 한다.

이 티켓의 존재 이유로 적힌 문장이 *"작문오염 모드로 3회차를 돌리면 컨텍스트가 얼마나 나빠지나를
몇 초에 물을 수 있게 한다"* 라, 스위치를 만들어 놓고 켤 길이 없으면 반쪽이다. 반대로 관측 출력을
여기서 다 만들면 #15 의 AC 를 통째로 당겨온다.

→ **스위치 조합을 인자로 받아 3회차를 돌리고, 지금 찍는 것을 그대로 찍는다.**
*"스위치 넷의 시그니처가 겹치지 않는다"* 는 주장은 마커 전용 테스트가 재기로 이미 정해져 있으므로
시뮬레이터가 표를 찍을 필요가 없다.
