# 회차를 시뮬레이션으로 대체하고, 그러기 위해 도메인을 프레임워크 밖에 둔다

외부 AI(STT·추출)를 테스트에서 호출하지 않는다. 대신 **동작을 모델링한 가짜**로 대체하고, 대본 여러 벌을 연속으로 흘려 **회차를 몇 초에 돌린다.**

이걸 가능하게 하는 전제가 하나 있다 — **도메인이 웹 프레임워크 밖에서 실행 가능해야 한다.**

## 병목은 비용이 아니라 회차다

이 설계의 핵심 주장은 전부 회차를 넘어야 확인된다. 용어집이 자라는가, 2회차 전사가 나아지는가, 후보가 누적되는가, 컨텍스트 한도가 언제 차는가.

그런데 **2회차를 보려면 일주일을 기다려야 한다.** 5회차면 한 달이고, 설계를 한 번 고칠 때마다 그 시간이 다시 든다.

비용은 회의당 $1~2라 문제가 아니다. **대체해야 할 것은 API 둘이 아니라 셋 — STT, 추출, 그리고 시간이다.**

## 가짜 STT는 재생이 아니라 오염 시뮬레이터다

녹화 재생만으로는 사슬을 테스트할 수 없다. 재생은 같은 입력에 같은 출력을 주는데, **사슬의 핵심 주장이 "컨텍스트가 바뀌면 전사가 달라진다"** 이기 때문이다.

그래서 실제 STT의 *동작*을 모델링한다. 대본(정답)과 오염 규칙을 따로 두고, 컨텍스트에 있는 용어는 정확히, 없는 용어는 규칙대로 깨뜨린다. 역방향 오인식도 같은 규칙으로 재현한다.

```
1회차 (컨텍스트 없음)   리버스 프록시는 캐디로 가죠 / 응답 캐시를 걸어두면
                        → 용어 후보 "캐디" → 확인 → 용어집 Caddy
2회차 (용어집 있음)     리버스 프록시는 Caddy로 가죠 / 응답 Caddy를 걸어두면
                                                        └ 대가까지 재현된다
```

시드를 고정하면 결정적이고, **사슬 전체를 assert할 수 있다.**

**단, 시뮬레이터는 빈도를 측정하지 못한다.** 역방향 오인식이 얼마나 자주 나는지는 우리가 넣은 규칙의 함수라 순환이다. 빈도는 실측이 주고, 시뮬레이터가 하는 건 **"오인식이 일어났을 때 시스템이 어떻게 되는지"** 다.

## 가짜 추출기는 마커 대본이다

대본에 정답을 미리 달아두고 가짜 추출기가 그걸 읽는다. LLM을 안 부르고 도메인·화면·사슬이 전부 돈다.

그리고 **실패 모드에 스위치를 단다** — 과잉분할, 제목오염, 누락, 담당자없음. *"제목오염 모드로 3회차를 돌리면 컨텍스트가 얼마나 나빠지나"* 같은 질문이 몇 초에 답해진다. 실제로는 몇 달 걸릴 관측이다.

## 두 겹을 구분한다

| | 입력 | 검증하는 것 |
|---|---|---|
| **재생 어댑터** | 녹화된 공급자 응답 | **정규화** — 공급자 JSON → 회의록 변환이 맞는가 |
| **오염 시뮬레이터** | 대본 + 오염 규칙 | **사슬** — 컨텍스트가 전사를 바꾸는가 |

재생은 현실에 묶여 있고 시뮬레이터는 우리가 만든 세계다. 목적이 다르므로 섞지 않는다.

## 따라오는 것

- **도메인이 프레임워크 밖에 있어야 한다.** 회차 시뮬레이터가 개발 루프의 중심인데 매번 프레임워크 컨텍스트를 띄우면 그 루프가 느려진다. 이 경계는 스택 선택보다 중요하다 ([stack.md](../stack.md))
- **운영 기능이 테스트 인프라를 공짜로 준다.** 공급자 원본 응답을 보관하고 추출 결과에 프롬프트 해시를 붙이기로 한 결정([seams.md](../seams.md))이 그대로 픽스처가 된다. 손으로 목 데이터를 만들 필요가 없다
- **CI에서 0원에 돈다.** 오디오조차 필요 없다 — 가짜 STT는 대본을 받는다
- **쓸수록 자산이 쌓인다.** 확인 화면에서 사람이 확정한 이슈가 곧 정답 라벨이다. 확인은 어차피 사람이 하는 일이므로 라벨링 비용이 0이다

## 추출 품질은 테스트가 아니다

"이슈가 쓸만하게 뽑혔나"는 assert할 수 없다. 정답이 없다.

대신 순서 0번(스파이크)에서 사람이 만든 **기준선**과 비교해 두 숫자를 센다 — **누락**(기준선에 있는데 안 뽑힘)과 **과잉**(뽑혔는데 기준선에 없음). 자동 채점은 하지 않는다. 이슈 문장이 매번 다르게 표현돼 문자열 비교가 안 되고, LLM 채점은 이 규모에 과하다.

**누락 쪽에만 임계를 건다.** *과잉추출은 사람이 5초에 버리지만 누락은 영원히 모른다*([mvp-scope.md](../mvp-scope.md)).

## 대가

**시뮬레이터가 현실에서 떨어져 나갈 수 있다.** 가짜가 계약을 어기면 테스트가 거짓 안전을 준다.

두 가지로 막는다:

- **같은 계약 테스트 스위트를 진짜 어댑터에도 돌린다.** CI가 아니라 손으로, 순서 0번과 실측 때
- **오염 규칙은 실측에서만 채운다.** 상상으로 지어내면 그 순간 시뮬레이터가 우리 상상을 검증하게 된다

```
실측  →  시뮬레이터를 교정한다
시뮬레이터  →  설계를 검증한다
```

[mvp-scope.md](../mvp-scope.md)가 *"실측은 C층을 뒤집고, 회의를 지면에서 돌려보는 것은 A층의 빈칸을 찾는다"* 고 한 분업이 그대로 코드가 된다. 다른 점은 지면이 아니라 자동이고, 몇 초라는 것뿐이다.

## 이 결정이 뒤집히는 경우

- **오염 규칙을 실측으로 채울 수 없을 때** — 실제 오류가 규칙으로 표현 안 될 만큼 무작위면 시뮬레이터가 현실을 못 흉내 낸다
- **회차가 병목이 아니게 될 때** — 회의를 주 3회 이상 하면 실측이 시뮬레이션보다 빨라진다
