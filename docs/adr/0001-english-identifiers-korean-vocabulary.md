# 식별자는 영문으로 쓰고, 도메인 어휘는 한국어로 남긴다

타입·함수·필드·지역변수·DB 컬럼 이름은 **영문**이다. `CONTEXT.md` 의 용어집은 **한국어로 남고**, 코드는 그 용어에 대응하는 영문 이름을 쓴다.

**이름은 영문, 말은 한국어.** 이 한 줄이 규칙이다.

## 왜

도구가 영문 식별자를 전제로 굴러간다. 스택 트레이스, 검색, 라이브러리 API, 에디터 자동완성이 전부 그렇다. 반대로 팀이 회의에서 쓰는 말은 한국어이고, 용어집이 그 말을 지켜야 코드 이름이 팀의 말을 끌고 가지 않는다.

용어집 어휘를 그대로 식별자로 옮기면 번역이 아니라 받아쓰기가 된다. 그러면 같은 개념이 한 파일 안에서 영문과 한글로 갈린다.

## 무엇이 영문이고 무엇이 한국어인가

| | 언어 | 예 |
|---|---|---|
| 타입 · 함수 · 필드 · 지역변수 | 영문 | `Meeting`, `transcribe()` |
| DB 테이블 · 컬럼 | 영문 | `meeting(id, audio_path)` |
| JSON 키 | 영문 | `{"question": "…", "answer": null}` |
| 주석 · 커밋 메시지 · 문서 | 한국어 | 그대로 |
| 화면에 나가는 말 | 한국어 | `<th>질문</th>` |
| DB · API 에 담기는 **값** | 한국어 | 상태 값이 생기면 한국어 그대로 |
| 테스트 이름 | 한국어 | `test("회의록이 비면 후보도 비어 있다", …)` |

테스트 이름은 문장으로 읽히는 것이 목적이라 한국어다. 값은 식별자가 아니라 데이터이고 화면에 그대로 뜨므로 한국어다.

## 용어집과 코드 이름의 대응

`CONTEXT.md` 가 정본이고 코드는 아래 대응을 따른다. 새 용어가 생기면 여기에 한 줄을 더한다.

| 용어집 | 코드 |
|---|---|
| 회의 | `Meeting` (표: `meeting`) |
| 회의록 | `Transcript` (표: `transcript`) |
| 이슈 후보 | `IssueCandidate` (표: `issue_candidate`) |
| 질문 | `question` |
| 답 | `answer` |

## 대가

용어집과 코드 사이에 번역 한 겹이 생긴다. 위 대응표가 그 겹을 한곳에 모아 두지만, 표가 낡으면 겹이 새는 자리가 된다.

## 뒤집히는 경우

- 팀이 영어를 읽는 비용이 번역 비용보다 크다고 판명될 때. 6인 팀이 아직 코드를 읽어 본 적이 없다
- 도구가 한글 식별자를 1급으로 다루게 될 때
