# 식별자는 영문으로 쓰고, 도메인 어휘는 한국어로 남긴다

클래스·메서드·필드·지역변수·DB 컬럼 이름은 **영문**이다. `CONTEXT.md` 의 용어집은 **한국어로 남고**, 코드는 그 용어에 대응하는 영문 이름을 쓴다.

## 왜 지금 정하는가

**정한 적이 없어서다.** 코드는 처음부터 한글 식별자로 쓰였는데, 그 선택을 정당화한 기록이 저장소 어디에도 없다.

- `CLAUDE.md` · `README.md` · `docs/stack.md` · ADR 0001~0005 · `CONTEXT.md` 어디에도 명명 규약이 없다
- 걷는 뼈대 커밋(`cb364cd`)은 모듈 분할 · boundaryCheck · 오케스트레이터 거처 · 단위작업 · 마이그레이션 정본 · 묶음 포트 **여섯 결정을 문단으로 정당화**하면서 식별자 언어는 한 글자도 말하지 않는다
- 이슈·PR 코멘트에도 없다

되돌리기 비용으로 결정을 분류하고([mvp-scope.md](../mvp-scope.md)의 *세 개의 층*) 티켓마다 설계 합의문을 쓰는 저장소에서 이 침묵은 하나를 뜻한다 — **결정으로 취급된 적이 없다.**

### 어디서 왔나

문서를 코드로 **음역**한 결과다. 두 자리가 그렇게 시켰다.

**`docs/agents/domain.md`** 가 용어집 어휘를 쓰라고 지시하면서 예시에 코드 이름을 섞었다:

> When your output names a domain concept (in an issue title, a refactor proposal, a hypothesis, **a test name**), use the term as defined in `CONTEXT.md`.

산문 예시들 사이에 **코드 식별자가 하나 끼어 있고**, 바로 다음 줄이 용어집은 한국어라고 못박는다. 테스트 이름이 한글이 되면 메서드 이름까지 한 걸음이다.

**`docs/seams.md`** 는 포트 표면을 한글 의사코드로 적어 뒀고, 이슈 수용 기준이 *"그 표면대로 선다"* 를 요구했다. 그래서 번역이 아니라 받아쓰기가 됐다.

### 음역이었다는 증거

같은 문서 블록에서 나온 두 레코드가 같은 파일 안에서 갈려 있었다.

```java
record Utterance(String speakerLabel, double startSec, double endSec, String text) {}   // 전부 영문
record TranscriptionResult(List<Utterance> 회의록, List<ContextItem> 반영된컨텍스트, …)   // 전부 한글
```

`seams.md` 에는 `발화구간 { 화자라벨?, 시작초, 끝초, 텍스트 }` 와 `회의록 + 반영된컨텍스트 + …` 가 나란히 한글로 적혀 있다. 판단이 있었다면 둘이 갈릴 이유가 없다.

## 무엇이 영문이고 무엇이 한국어인가

| | 언어 | 예 |
|---|---|---|
| 타입 · 메서드 · 필드 · 지역변수 | **영문** | `RoundOrchestrator.transcribe()`, `Term(spelling, meaning)` |
| DB 테이블 · 컬럼 | **영문** | `glossary(spelling, meaning)` |
| JSON 키 | **영문** | `{"spelling": "…", "meaning": null}` |
| 주석 · javadoc · 커밋 메시지 · 문서 | **한국어** | 그대로 |
| 화면에 나가는 말 | **한국어** | `<TableHead>표기</TableHead>` |
| DB · API 에 담기는 **값** | **한국어** | `job.state = '처리중'`, `issue.state = '쟁점'` |
| 테스트 **메서드** 이름 | **한국어** | `void 컨텍스트에_용어를_넣으면_고착이_사라진다()` |

**이름은 영문, 말은 한국어.** 이 한 줄이 규칙이다.

### 예외 둘의 근거

**테스트 메서드 이름**은 국내 자바에서 통용되는 관행이고, 문장으로 읽히는 것이 그 이름의 목적이다. `domain.md` 가 명시적으로 허용하던 자리이기도 하다 — 다만 그 허용을 *테스트 이름에 한정*하도록 문구를 고쳤다.

**상태 값**은 식별자가 아니라 데이터다. `issue_candidate.state` 가 한글을 담기로 한 것은 #3 합의문이 이미 정한 것이고, 그 값이 화면에 그대로 뜬다. 그래서 `enum State { 쟁점, 결정, 실행됨, 무효 }` 는 상수 이름이 곧 저장 값이라 한국어로 남는다. 이름을 영문으로 바꾸면 저장된 값과 화면 표기가 함께 바뀐다 — 명명 문제가 아니라 데이터·계약 변경이다.

## 용어집과 코드 이름의 대응

`CONTEXT.md` 가 정본이고 코드는 아래 대응을 따른다. 새 용어가 생기면 여기에 한 줄을 더한다.

| 용어집 | 코드 |
|---|---|
| 이슈 · 쟁점 · 결정 · 실행됨 · 무효 | `Issue`, `State.쟁점` … |
| 후보 | `IssueCandidate` · `TermCandidate` |
| 확인 | `confirm` |
| 회의 | `Meeting` · `MeetingId` |
| 회의록 | `Transcript` (표: `transcript`) |
| 용어집 | `Glossary` |
| 용어 | `Term` |
| 표기 | `spelling` |
| 뜻 | `meaning` |
| 명단 | `roster` |
| 근거 | `Evidence` (표: `…_evidence`) |
| 의견 | `Opinion` |
| 할 일 | `Task` |
| 추출 | `Extraction` (표: `extraction`) |
| 로컬키 | `LocalKey` |

**`할 일` 을 `Task` 로 옮긴다.** `CONTEXT.md` 의 `_Avoid_: 태스크, 액션 아이템, 투두` 가 셋 다 영어 음역인데, 이 ADR 이 *"이름은 영문, 말은 한국어"* 로 두 축을 이미 갈랐다. 금지된 것은 한국어로 그렇게 부르는 것이고, `ActionItem` · `Todo` 는 오히려 그 음역과 한 글자씩 붙어 있다.

**뜻을 `definition` 이 아니라 `meaning` 으로 옮긴다.** `CONTEXT.md` 가 *"뜻은 회의록에서 인용하지 사람이 작문하지 않는다"* 고 못박았는데 `definition` 은 작문된 것을 가리킨다.

## 대가

**용어집과 코드 사이에 번역 한 겹이 생긴다.** 한글 식별자의 유일한 진짜 장점이 그 겹이 없다는 것이었다. 위 대응표가 그 겹을 한곳에 모아 두지만, 표가 낡으면 겹이 새는 자리가 된다.

**이 결정은 소급되지 않는다.** `docs/design/` 의 설계 합의문들은 그날 합의된 것의 기록이라 한글 이름 그대로 둔다. 지금 코드를 가리키는 문서(`seams.md`)만 영문 이름을 병기한다.

## 이 결정이 뒤집히는 경우

- **팀이 영어를 읽는 비용이 번역 비용보다 크다고 판명될 때.** 이 저장소는 아직 한 사람이 썼고, 6인 팀이 실제로 코드를 읽어 본 적이 없다
- **도구가 한글 식별자를 1급으로 다루게 될 때.** 지금은 jOOQ 코드 생성·스택 트레이스·검색이 전부 영문을 전제로 굴러간다
