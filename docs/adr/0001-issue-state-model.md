# 회의 산출물을 상태 가진 이슈로 모델링한다

회의 산출물을 "결정의 평면 목록"이 아니라 **상태를 가진 이슈**로 모델링한다. 이슈는 팀이 하나의 답을 내야 하는 질문이며, 쟁점(답 없음) → 결정 → 실행됨의 상태를 갖고 무효로 끝날 수도 있다.

결정만 기록하면 **아직 정해지지 않은 것**이 아무 흔적도 남기지 못한다. 팀이 서로 다르게 이해하는 가장 흔한 원인은 결정을 다르게 기억하는 것이 아니라, 안 정해진 것을 정해졌다고 착각하는 것이다. 그 어긋남은 누군가 그 전제 위에 일을 다 해놓은 뒤에야 드러난다. 미결을 1급으로 다루려면 상태가 필요하다.

## 따라오는 것

- **관련 이슈 찾기가 공짜가 된다.** 태그나 카테고리를 따로 만들 필요 없이 이슈 자체가 축이 된다.
- **모순과 번복이 구분된다.** 기계가 보기에 둘은 똑같이 "이전과 반대되는 새 답"이지만, 이 모델에서 정상 경로는 번복(재열기 → 재결정) 하나뿐인 명시적 전이다.
- **입도가 강제된다.** 이슈는 하나의 답으로 결정될 수 있는 크기여야 한다. 굵게 잡으면 모든 이슈가 영원히 쟁점 상태에 머물러 상태가 아무 정보도 담지 못한다.

## 대가

회의에서 나온 결정이 항상 질문 형태로 시작하지는 않는다("그냥 이렇게 하죠"). 이 경우 질문을 역으로 합성해야 하며, 어색하거나 과하게 잘게 쪼개질 수 있다. **실제 회의로 검증이 필요한 지점이며, 이 모델 전체가 여기에 걸려 있다.**
