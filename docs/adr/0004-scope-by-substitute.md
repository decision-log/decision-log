# 범위를 대체재 유무로 자른다

무엇을 만들지는 "이게 있으면 좋은가"가 아니라 **"안 만들면 팀이 무엇을 하는가"** 로 정한다.

이 기준으로 자른 결과가 **v0.5**다 — 오디오가 들어가면 사람 손 없이 이슈 로그가 되고, 그 로그가 다음 회의의 전사 품질을 올리는 **사슬**. 그리고 사슬에 깨진 데이터가 들어가는 것을 막는 최소한의 확인.

## 왜 기준을 바꿨나

처음 잰 것은 "각 범위가 기능을 다 써보게 하는가"였다. 그 기준은 답이 정해져 있다 — 기능 커버리지로 재면 언제나 "더 만들어라"가 나온다.

"안 만들면 팀이 무엇을 하는가"로 바꾸자 대부분의 기능에 대체재가 드러났다. 클로바노트가 전사·화자 분리·요약을 하고, 회의록을 LLM에 붙여넣으면 이슈가 뽑히고, 노션이 이슈와 할 일을 상태로 관리하고, 카톡이 회의 전 후보 등록을 한다. 전부 이미 쓸 수 있고 대부분 무료다.

**대체재 스택은 기능적으로 거의 다 된다. 무너지는 건 지속성이다.** 회의마다 사람 손 10~15분을 요구하고, 그 손은 3회차쯤 사라진다. 그게 문제 2(*서기가 필요한데 인원이 없다*)의 재현이고, 컨텍스트를 손으로 넣는 번거로움은 [stt-requirements.md](../stt-requirements.md)에서 이미 실측으로 증명된 실패다.

그래서 우리가 만드는 것은 기능 묶음이 아니라 **손이 안 가는 연결**이다.

## 판정 규칙

| | 규칙 |
|---|---|
| 1 | **대체재가 없으면 만든다** — 사슬(자동 연결)만 여기 해당한다 |
| 2 | **대체재가 회의마다 사람 손을 요구하면(△약) 만든다** — 3회차에 멈추므로 사실상 대체재가 아니다 |
| 3 | **대체재가 손 없이 지속되면(△강) 안 만든다** |
| 4 | **사슬에 깨진 데이터가 들어가는 걸 막는 건 △여도 만든다** — 오류가 회차를 넘어 증폭된다 |
| 5 | **4에 해당해도 사슬 기여가 0이면서 비싸면 뺀다** |

△를 두 종류로 가른 것이 이 규칙의 핵심이다. **△강**은 대체재가 회의마다 손을 요구하지 않아 지속되고, **△약**은 요구해서 멈춘다. 약한 △는 사실상 대체재가 아니다.

## 만드는 것

**파이프라인 — 사람 손 0**

| | |
|---|---|
| 오디오 업로드 | 회의 하나 = 파일 하나 |
| STT 어댑터 | 인터페이스 뒤 ([seams.md](../seams.md)) |
| 추출 | **전량 뽑아 전량 저장.** 화면이 없어도 뽑는다 |
| 저장 | **A층 스키마 전체** — 화면만 자르고 모델은 안 자른다 |
| 컨텍스트 조립 | 다음 회의 STT로. **이 제품의 유일한 O** |

**화면 — 최소**

| | 왜 |
|---|---|
| 한 줄 후보 등록 | 컨텍스트 소스 3의 유일한 사람 입력구 |
| 미확인 후보·쟁점 목록 | 회의 절차 2번. 이슈 목록에 필터 하나 |
| 확인 2장 — **이슈**(제목 교정·상태·후보 회수·연결) / **용어**(표기 O/X) | 규칙 4 |
| 이슈 목록 · 회의 목록 | 읽기 |

재열기·번복·무효는 전용 UI를 만들지 않고 **1장의 상태 편집이 대신한다.** 기존 답이 근거로 남는 것은 스키마가 받는다.

## 안 만드는 것

| | 대체재 | 판정 |
|---|---|---|
| 할 일·담당자·완료·`실행됨` | 노션 / GitHub Issues / 카톡 | △강 — [ADR 0003](./0003-no-external-task-tool.md)의 탈출 조건이 발동한 상태 |
| 시작 라운드 개인 화면 | 지금도 말로 한다 | △강 |
| 이슈 상세(근거·의견·이력) | 회의록 원문 + 기억 | △강. 초기 회차엔 되짚을 게 없다 |
| 의견·화자 화면 | 저장은 하되 안 보여준다 | 컨텍스트에 안 나간다 |
| 화자 이름 매핑 | 익명 라벨로 저장 | 소비자가 없다 |
| 이슈 병합 | 목록에서 눈으로 센다 | 규칙 5. 과잉 분할 **관측**은 병합 없이도 된다 |
| MCP (v2) | 마크다운 붙여넣기, 노션 MCP | △중. 로그가 비면 가치 0 |
| 인증·멀티테넌시 | — | 원래 범위 밖 |

## 따라오는 것

- **사용자 식별이 필요 없어진다.** 담당자와 "자기 할 일 화면"이 빠지면서 "지금 나는 누구인가"를 물을 자리가 사라졌다. 공유 화면 하나로 끝난다
- **확인 화면의 정당화가 바뀐다.** "6명이 함께 보는 가치"가 아니라 **"사슬에 쓰레기가 안 들어가게 하는 장치"** 다. 그 기준이 절단면을 저절로 그어준다 — **컨텍스트로 나가는 것만 확인한다**
- **1~3회차는 서버가 필요 없다.** 대면 회의라 노트북 하나를 프로젝터에 물리면 된다 ([stack.md](../stack.md))

## 대가

- **문제 3(*6명이 다르게 이해한다*)이 절반만 풀린다.** 10분 정리는 20분 정리보다 약하다. [mvp-scope.md](../mvp-scope.md)가 가치가 가장 높다고 한 지점을 의도적으로 축소했다
- **문제 1도 절반이다** — 할 일이 도구 밖에 있으면 결정에서 나온 작업이 로그와 분리된다
- **△강 판정이 실측이 아니다.** 클로바노트·LLM 붙여넣기 조합이 실제로 얼마나 되는지는 안 재봤다. 재보면 등급이 움직일 수 있고, 그러면 이 결정도 움직인다

이 대가를 받는 근거는 **되돌리기 비용의 비대칭**이다. 안 만들었다가 나중에 만드는 건 화면 붙이는 값인데, **스키마는 A층 전체를 담았고 추출도 전량 했으며 오디오도 보존하므로 데이터가 이미 쌓여 있다.** 반대로 만들었는데 안 쓰면 회수가 안 되고, 안 쓰는 화면이 매 회의 정리 시간을 먹는다.

## 넓히는 신호

**이 신호가 오기 전에는 넣지 않는다.**

| 넣을 것 | 신호 |
|---|---|
| 할 일 + 시작 라운드 | 지난 회의 할 일을 아무도 기억 못 하는 회의가 나올 때 |
| 이슈 병합 | 회의 하나에서 이슈가 10개 넘게 쪼개질 때 |
| 이슈 상세 | "그때 누가 뭐라고 했지"를 회의 중에 두 번 이상 못 찾을 때 |
| 확인 화면 3·4장 | 10분 정리가 짧게 느껴질 때 |
| MCP | 이슈가 30건 넘고 AI 작업이 로그와 어긋나기 시작할 때 |
| 화자 이름 매핑 | 의견을 실제로 되짚고 싶어질 때 |
| 용어집 항목 삭제 | 용어집에서 지우고 싶은 항목이 눈에 띄기 시작할 때 |
| 연결 제안(2차 추출) | 쟁점이 20개를 넘어 사람이 눈으로 훑기 어려워질 때 |

## 이 결정이 뒤집히는 경우

- **대체재 실측이 △강을 뒤집을 때** — 클로바노트가 우리 회의에서 못 쓸 수준이거나, 반대로 노션 이관이 실제로는 3분이면 끝날 때
- **팀이 할 일 관리를 어디서도 안 하게 될 때** — 그러면 할 일은 △강이 아니라 △약이 되고 규칙 2가 발동한다
